01 · CONTROL FLOW

一條請求，怎麼走到可證明完成

先記住資料與權威的方向。關鍵不是步驟數，而是任何一個 binding 失配都必須停下。

01 · ROUTE選路與模式

意圖、能力與風險決定 template / mode。

02 · FREEZETaskContract

凍結 goal、scope、驗收、權限與 stages。

03 · BIND來源綁定

HEAD、index、status 與 sentinel 形成來源身分。

04 · DERIVELedger

Append-only events 重播成 ready / blocked / complete。

05 · PROVE型別證據

Producer、payload、digest 與 freshness 全部要成立。

06 · REVIEW精確審查

Finding 綁 exact diff；P0/P1 必須收斂。

07 · ACT一次性授權

短效 token 只允許固定 executable / argv。

08 · RECONCILE對帳再完成

Provider receipt 與最後 sentinel 決定終態。

02 · MENTAL MODEL

四件事，不能互相代替

這是理解整套系統最重要的分界：成功執行不等於有證據，有證據也不等於外部世界已完成。

01

執行成功

命令或 agent 回傳成功，只說明那次執行沒有直接失敗。

02

證據有效

證據必須符合 kind、producer、schema、freshness 與 digest。

03

外部已對帳

Provider 的實際狀態必須由 receipt 或查詢重建，而非相信本機呼叫。

04

可以宣告完成

重驗 ledger、review、evidence、sentinel 與 side effects 後才有終態。

03 · ASSURANCE MODES

Mode 是驗證強度，不是 agent 數

風險提高時，系統增加 governed run、fresh evidence、獨立 critics 與 fail-closed gates；mutation authority 仍在 root。

LEVEL 1 / 4

direct

低風險、可回復；root 直接執行，不建立 governed run。

LEVEL 2 / 4

verified

新鮮證據，加上 1–3 個唯讀 reviewer 做交叉驗證。

LEVEL 3 / 4

deep

在 verified wave 後加入獨立 Codex critics 與 broad review。

LEVEL 4 / 4

critical

不可逆副作用要求完整 authority、exact critic 與 reconciliation。

01 · REPLAY TAXONOMY

Replay 至少有三種語義

它們都用持久化輸入重建結論，但輸入、輸出和 failure policy 不同；reconciliation 更不是「再送一次」。

TYPE 01

Ledger replay

events → state

TaskContract + ordered events + admitted evidence 重建 ready set 與 task state。

TYPE 02

Evaluator replay

witnesses → comparison

Corpus、immutable snapshots、prompts 與 signed witnesses 重算分數和比較。

TYPE 03

Provider reconciliation

attempt → truth

同一 action attempt 對帳成 success / failure / unknown；禁止 blind retry。

02 · TRUST BOUNDARY

Repo 寫政策，Host 證明怎麼執行

Critical evaluator 的信任根在 candidate 無法修改的 host boundary，而不是 repo 內一段「請相信我」的程式。

01Source binding

Clean worktree、full SHA、candidate / baseline digests。

02Signed bundle

Root-owned path、binary、schema 與 compatibility。

03Launcher

固定 executable / cwd，限制 uid、gid 與環境。

04Loopback

Nonce-bound、單次請求、固定 upstream。

05Canonical body

Single user input、tools off、strict JSON schema。

06Envelope

Request、response、runtime、model、issuer 全綁定。

07Replay verify

驗簽、distinct witnesses、prompt 重建與 comparison。

08Decision

Tie、noise、regression 或 mismatch 都不產生 authority。

!
Blocked / indeterminate 是正確的產品狀態

缺 evidence、source drift、host 不可證明或 provider unknown 時，系統拒絕用猜測製造完成感。
