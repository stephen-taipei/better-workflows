Better Workflows 由维护者主导。

## 决策模式

- 维护者接受或拒绝项目级别的设计与版本发布变更。
- 证据、可复现的测试、安全边界、兼容性与维护成本，优先于受欢迎程度或多数投票结果纳入考量。
- 公开契约与安全边界的变更需要明确审查。
- 当新证据改变权衡结果时，遭到拒绝的提案可以重新考虑。

## 工作流权限

在 Better Workflows 运行中，Root 是唯一的变更与风险接受权威。该运行时规则不会赋予代码仓所有权，也不会覆盖 GitHub 权限。

## 版本发布

插件缓存构建版本不可变更。候选发布版本必须在发布前通过适用的测试、评估、证据时效性、证据、受保护分支，以及源代码／缓存核对关卡。

## 治理变更

治理变更须按公开契约变更进行审查，并且必须记录在仓库历史中。
