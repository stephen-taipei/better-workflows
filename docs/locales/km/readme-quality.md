## ចាប់ផ្ដើមពីការសម្រេចចិត្តរបស់អ្នកអាន

GitHub បង្ហាញ README មុនមាតិកាភាគច្រើនក្នុងឃ្លាំងកូដ។ ដូច្នេះ អេក្រង់ដំបូងត្រូវ បញ្ជាក់ការសន្យារបស់ផលិតផល ក្រុមអ្នកអានគោលដៅ និងសកម្មភាពបន្ទាប់ដែលមានដែនកំណត់ ច្បាស់លាស់។ វាមិនត្រូវចាប់ផ្ដើមដោយស្ថាបត្យកម្មខាងក្នុង ឯកសារយោងពាក្យបញ្ជាពេញលេញ ឬព័ត៌មានលម្អិតអំពីការស្ដារកំណែចេញផ្សាយទេ។

សរសេរដើម្បីបំពេញភារកិច្ចរបស់អ្នកអានទាំងនេះ៖

- **អ្នកចូលមើលថ្មី៖** សម្រេចចិត្តយ៉ាងឆាប់រហ័សថាតើ Better Workflows ដោះស្រាយ បញ្ហាពាក់ព័ន្ធដែរឬទេ។
- **អ្នកប្រើប្រាស់ថ្មី៖** ដំឡើងកម្មវិធីជំនួយ \(plugin\) ហើយសម្រេចបានផ្លូវស្វ័យប្រវត្តិជោគជ័យមួយ។
- **អ្នកវាយតម្លៃ៖** យល់ដឹងពីព្រំដែនអាជ្ញាធរ និងឥរិយាបថ fail\-closed។
- **ប្រតិបត្តិករត្រឡប់មកវិញ៖** ចូលទៅកាន់ចម្លើយ workflow សុវត្ថិភាព ស្ថាបត្យកម្ម ឬ CLI ភ្លាមៗ។
- **អ្នករួមចំណែក ឬអ្នកបកប្រែ៖** ស្វែងរកកិច្ចសន្យាគោល ពាក្យបញ្ជាអភិវឌ្ឍន៍ ការគាំទ្រ និងអភិបាលកិច្ច។

កុំដាក់ស្ទួនការស្ដារឃ្លាំងទិន្នន័យបណ្ដោះអាសន្ន សិទ្ធិកាន់កាប់ការចាក់សោ ន័យពេញលេញនៃការដឹកជញ្ជូនទិន្នន័យរបស់អ្នកផ្ដល់សេវា បញ្ជីពាក្យបញ្ជាគ្រប់ជ្រុងជ្រោយ ឬប្រវត្តិការផ្លាស់ប្ដូរការអនុវត្ត នៅលើទំព័រច្រកចូល។ ការអះអាងសុវត្ថិភាពខ្លីគួរនៅលើទំព័រនោះ ចំណែកព័ត៌មានស៊ីជម្រៅដែលអាចធ្វើសវនកម្មបានរបស់វា ត្រូវដាក់ ក្នុងមគ្គុទ្ទេសក៍គោល។

ការបំបែកនេះអនុវត្តតាមការបែងចែករបស់ Diátaxis រវាងមេរៀនណែនាំ មគ្គុទ្ទេសក៍ អនុវត្ត សេចក្ដីពន្យល់ និងឯកសារយោង។ ទំព័រតែមួយមិនអាចធ្វើឱ្យល្អបំផុតសម្រាប់តម្រូវការអ្នកអានទាំងបួន ក្នុងពេលតែមួយបានទេ។

## ឱ្យធាតុរូបភាពនីមួយៗមានហេតុផលសមនឹងកន្លែងរបស់វា

ប្រើធាតុរូបភាពតែនៅពេលដែលទំនាក់ទំនង ឋានានុក្រម ឬការផ្លាស់ប្ដូរស្ថានភាព អាចយល់បានងាយជាងអត្ថបទធម្មតាយ៉ាងច្បាស់លាស់។

ទំព័រច្រកចូលអនុញ្ញាតឱ្យមានធាតុរូបភាពពីរ៖

1. **ស្ថាបត្យកម្មព្រំដែនសិទ្ធិអំណាច\:** ឆ្លើយថាស្រទាប់ណាខ្លះកំណត់ចេតនា ការពិតបច្ចុប្បន្ន សិទ្ធិអំណាចឧបករណ៍ ការព្យាយាមឡើងវិញដែលមានដែនកំណត់ និងស្ថានភាពសម្រាប់តែអាន។
2. **វដ្តជីវិតពីគោលដៅដល់ការបញ្ចប់\:** ឆ្លើយថាកន្លែងណាត្រួតពិនិត្យភស្តុតាង កន្លែងណា អនុញ្ញាតផលប៉ះពាល់បន្ទាប់បន្សំ និងកន្លែងណាដែលស្ថានភាពមិនស្គាល់បញ្ឈប់ការរីកចម្រើន។

ធាតុរូបភាពនីមួយៗត្រូវមាន៖

- អត្ថបទជំនួសខ្លី និងមានន័យ\;
- អត្ថបទសមមូលនៅក្បែរ ដែលរក្សាសេចក្ដីសន្និដ្ឋាននៅពេលធាតុរូបភាព ត្រូវបានលាក់ ឬ Mermaid មិនបង្ហាញ\;
- អត្ថបទពិតប្រាកដសម្រាប់ស្លាកសំខាន់ៗ នៅពេលណាដែលអាចធ្វើបាន\;
- សំណួររបស់អ្នកអានដែលនៅតែមានសុពលភាពយូរអង្វែង និងផ្ដល់ហេតុផលសម្រាប់រក្សាធាតុរូបភាពឱ្យទាន់សម័យ។

កុំបន្ថែមរូបថតអេក្រង់សម្រាប់តុបតែង រូបភាពដែលមានអត្ថបទច្រើនពេក ឬដ្យាក្រាមដែលគ្រាន់តែ ស្ទួនបញ្ជីខ្លីមួយ។ កំណត់តារាងជ្រើសរើសឱ្យមានតែពីរជួរឈរដែលមានខ្លឹមសារខ្លី ដើម្បីឱ្យវា នៅតែអាចប្រើបានលើអេក្រង់តូចចង្អៀត។

## រក្សាអត្ថន័យឱ្យដូចគ្នារវាងភាសា

ភាសាអង់គ្លេសជាឯកសារយោងផ្នែកន័យ មិនមែនជាគោលដៅសម្រាប់ចំនួនបន្ទាត់ទេ។ ភាសាចិនអក្សរបុរាណ ភាសាចិនអក្សរសាមញ្ញ ភាសាជប៉ុន និងភាសាកូរ៉េ គួរអានទៅមានលក្ខណៈធម្មជាតិសម្រាប់អ្នកអាន ដែលជាម្ចាស់ភាសា ខណៈពេលរក្សាកិច្ចសន្យាដូចគ្នា។

ធាតុខាងក្រោមត្រូវនៅតែសមមូលគ្នា៖

- ផ្នែកន័យទាំងប្រាំបី និងលំដាប់របស់វា\;
- ពាក្យបញ្ជាសម្រាប់ភាពជោគជ័យដំបូង និងអត្តសញ្ញាណផលិតផល\;
- ការអះអាងទាំងប្រាំអំពីសិទ្ធិអំណាច ភស្តុតាង ស្ថានភាពមិនស្គាល់ សំណើណែនាំម៉ូដែល និងឯកជនភាព\;
- ទិសដៅតំណទៅលំហូរការងារ សន្តិសុខ ស្ថាបត្យកម្ម CLI ជំនួយ អភិបាលកិច្ច ការអភិវឌ្ឍ និង អាជ្ញាបណ្ណ\;
- គោលបំណងរបស់ធាតុរូបភាព ដំណាក់កាលនៃវដ្តជីវិត និងអត្ថបទជំនួស\;
- ប្រភពព័ត៌មានកំណែ និងគោលនយោបាយផ្លាកសញ្ញា។

ចំណងជើង ការបែងចែកប្រយោគ វណ្ណយុត្តិ ឧទាហរណ៍ និងសារអំពាវនាវឱ្យធ្វើសកម្មភាព អាច ប្រើសំនួនធម្មជាតិនៃភាសានីមួយៗ។ កុំបកប្រែពាក្យបញ្ជា ឧបករណ៍ជ្រើសរើស អត្តសញ្ញាណភស្តុតាង ឬ ន័យសន្តិសុខជាដាច់ខាត។

## សរសេរសម្រាប់ការអានមើលរហ័ស និងការបកប្រែ

- ចាប់ផ្ដើមដោយលទ្ធផលសម្រាប់អ្នកអាន ហើយដាក់ពាក្យសំខាន់ៗនៅខាងដើម ចំណងជើង និងកថាខណ្ឌ។
- ប្រើទម្រង់ប្រយោគសកម្ម ហើយបញ្ជាក់តួអង្គដែលទទួលខុសត្រូវចំពោះសកម្មភាព។
- និយាយទៅកាន់អ្នកអានដោយផ្ទាល់ក្នុងការណែនាំនីតិវិធី។
- រក្សាកថាខណ្ឌឱ្យខ្លី ហើយឱ្យកថាខណ្ឌនីមួយៗមានតួនាទីតែមួយ។
- ប្រើបញ្ជីមានលេខសម្រាប់លំដាប់ និងបញ្ជីចំណុចសម្រាប់ជម្រើសដែលមិនមានលំដាប់។
- ប្រើតំណដែលពិពណ៌នាខ្លឹមសារ ជំនួសស្លាកទូទៅដូចជា «ចុចទីនេះ»។
- រក្សាចំណងជើងឱ្យមានឋានានុក្រម ជាក់លាក់ និងមានទម្រង់ស្របគ្នានៅកម្រិតដូចគ្នា។
- ផ្ដល់អាទិភាពដល់ភាសាត្រង់ន័យ មិនស្រពិចស្រពិល ដែលរក្សាអត្ថន័យបានក្រោយការបកប្រែ។
- ដាក់លក្ខខណ្ឌមុនសេចក្ដីណែនាំ និងដាក់លទ្ធផលរំពឹងទុកក្រោយពាក្យបញ្ជា។

## ផ្ទៀងផ្ទាត់ន័យ មិនមែនការតុបតែង

តេស្តឯកសារត្រូវរកឃើញលើសពីការផ្គូផ្គងចំណងជើង។ វាផ្ទៀងផ្ទាត់៖

- H1 មួយ និងឋានានុក្រមចំណងជើងសមហេតុផល\;
- ផ្នែក semantic ដែលមានលំដាប់លំដោយ និងសញ្ញាសម្គាល់ការទាមទារសំខាន់ៗ\;
- ពាក្យបញ្ជាជោគជ័យលើកដំបូងជាក់លាក់ និងឧបករណ៍កំណត់អត្តសញ្ញាណមានស្ថេរភាព\;
- តំណភ្ជាប់ដែលទាក់ទងគ្នា និងគោលដៅលម្អិតជាក់លាក់តាមភាសា\;
- ភាពត្រូវគ្នានៃផ្លាកសញ្ញាកំណែ \(version badge\) ជាមួយទិន្នន័យមេតា runtime\;
- អត្ថបទជំនួសរូបភាព \(alt text\) មានអត្ថន័យ និងរូបភាពជំនួសដែលនៅជាប់គ្នា\;
- វដ្តជីវិត Mermaid តែមួយដែលមានអត្ថបទសមមូលពេញលេញ\;
- ថវិកាតារាងពីរជួរឈរ និងប្រវែងកថាខណ្ឌ\;
- អវត្តមាននៃព័ត៌មានលម្អិតអំពីការអនុវត្តស៊ីជម្រៅដែលបានកំណត់ពី landing page\;
