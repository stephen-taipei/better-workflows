Better Workflows ကို စီမံထိန်းသိမ်းသူက ဦးဆောင်သည်။

## ဆုံးဖြတ်ချက်ချမှတ်မှုပုံစံ

- စီမံထိန်းသိမ်းသူသည် စီမံကိန်းအဆင့် ဒီဇိုင်းနှင့် ဖြန့်ချိမှုဆိုင်ရာ ပြောင်းလဲမှုများကို လက်ခံ သို့မဟုတ် ငြင်းပယ်သည်။
- အထောက်အထား၊ ပြန်လည်ပြုလုပ်နိုင်သော စမ်းသပ်မှုများ၊ ဘေးကင်းရေးနယ်နိမိတ်များ၊ လိုက်ဖက်ညီမှုနှင့် ထိန်းသိမ်းရေးကုန်ကျစရိတ်ကို လူကြိုက်များမှု သို့မဟုတ် အများစုမဲထက် ဦးစားပေးစဉ်းစားသည်။
- အများပြည်သူဆိုင်ရာ သဘောတူသတ်မှတ်ချက်နှင့် လုံခြုံရေးနယ်နိမိတ် ပြောင်းလဲမှုများသည် အတိအလင်း ပြန်လည်သုံးသပ်မှု လိုအပ်သည်။
- အထောက်အထားအသစ်က အကျိုးအပြစ်ချိန်ဆမှုကို ပြောင်းလဲစေပါက ငြင်းပယ်ထားသော အဆိုပြုချက်ကို ပြန်လည်စဉ်းစားနိုင်သည်။

## အလုပ်စီးဆင်းမှုဆိုင်ရာ လုပ်ပိုင်ခွင့်

Better Workflows run တစ်ခုအတွင်း Root သည် တစ်ခုတည်းသော mutation နှင့် အန္တရာယ်လက်ခံမှု အခွင့်အာဏာဖြစ်သည်။ ဤ runtime စည်းမျဉ်းသည် repository ပိုင်ဆိုင်ခွင့်ကို ပေးအပ်ခြင်း သို့မဟုတ် GitHub ခွင့်ပြုချက်များကို ကျော်လွန်လုပ်ဆောင်ခြင်း မရှိပါ။

## ဖြန့်ချိမှုများ

ပလပ်အင်ကက်ရှ် တည်ဆောက်ဗားရှင်းများသည် ပြောင်းလဲ၍မရပါ။ ထုတ်ဝေရန်လျာထားသောမူသည် သက်ဆိုင်ရာ စမ်းသပ်မှု၊ အကဲဖြတ်မှု၊ အထောက်အထား၏ အချိန်မီမှု၊ အထောက်အထား၊ ကာကွယ်ထားသော ကုဒ်အကိုင်းနှင့် မူရင်း\/ကက်ရှ် တိုက်ဆိုင်ညှိနှိုင်းစစ်ဆေးမှုဆိုင်ရာ စစ်ဆေးတံခါးများကို ထုတ်ဝေခြင်းမပြုမီ အောင်မြင်ရမည်။

## အုပ်ချုပ်စီမံမှု ပြောင်းလဲခြင်း

အုပ်ချုပ်စီမံမှု ပြောင်းလဲမှုများကို အများပြည်သူဆိုင်ရာ သဘောတူသတ်မှတ်ချက် ပြောင်းလဲမှုများအဖြစ် ပြန်လည်သုံးသပ်ပြီး ကုဒ်သိုလှောင်ရာသမိုင်းတွင် မှတ်တမ်းတင်ရမည်။
