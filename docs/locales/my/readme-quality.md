Better Workflows ၏ README သည် မိတ်ဆက်စာမျက်နှာဖြစ်ပြီး ချုံ့ထားသော ကိုးကားလက်စွဲ မဟုတ်ပါ။ ၎င်း၏တာဝန်မှာ စာဖတ်သူကို အောက်ပါမေးခွန်းငါးခုအား အစဉ်လိုက် ဖြေနိုင်ရန် ကူညီပေးခြင်းဖြစ်သည်\:

1. ဤအရာသည် ဘာလဲ၊ ကျွန်ုပ်အတွက် သင့်တော်သလား\?
2. မည်သည့်ပြဿနာကို ဖြေရှင်းပေးသလဲ\?
3. ၎င်း၏အဆိုများကို အဘယ်ကြောင့် ယုံကြည်သင့်သလဲ\?
4. ပထမဆုံးအောင်မြင်မှုရရန် အတိုဆုံးလမ်းကြောင်းက ဘာလဲ\?
5. နောက်တစ်ဆင့် ဘယ်ကိုသွားသင့်သလဲ\?

ဤစီမံပုံသည် ကုဒ်သိုလှောင်ရာရှိ README တိုင်းအတွက် အကြောင်းအရာတင်ပြပုံ၊ ရုပ်ပုံ၊ ဒေသသုံးဘာသာပြန်နှင့် အတည်ပြုစစ်ဆေးမှုဆိုင်ရာ လိုက်နာရမည့် သဘောတူသတ်မှတ်ချက်ကို သတ်မှတ်သည်။ စက်ဖြင့်ဖတ်နိုင်သော မူရင်းမှာ [`readme-quality-v1.json`](../../../plugins/better-workflows/config/readme-quality-v1.json) ဖြစ်သည်။

## စာဖတ်သူ၏ ဆုံးဖြတ်ချက်မှ စတင်ပါ

GitHub သည် ကုဒ်သိုလှောင်ရာအကြောင်းအရာအများစုထက် README ကို အရင်ပြသသည်။ ထို့ကြောင့် ပထမမြင်ကွင်းတွင် ထုတ်ကုန်၏ကတိ၊ ရည်ရွယ်သည့်ပရိသတ်နှင့် နယ်ပယ်ကန့်သတ်ထားသော နောက်လုပ်ဆောင်ချက်ကို ရှင်းလင်းစွာ ဖော်ပြရမည်။ အတွင်းပိုင်းဗိသုကာဖွဲ့စည်းပုံ၊ အမိန့်ကိုးကားချက်အပြည့်အစုံ သို့မဟုတ် ထုတ်ဝေမှုကို ပြန်လည်ရယူရေးအသေးစိတ်ဖြင့် မစတင်ရပါ။

စာဖတ်သူတို့၏ အောက်ပါတာဝန်များအတွက် ရေးသားပါ\:

- **ဧည့်သည်အသစ်\:** Better Workflows သည် သက်ဆိုင်ရာ ပြဿနာကို ဖြေရှင်းနိုင်ခြင်း ရှိမရှိ အမြန်ဆုံး ဆုံးဖြတ်ပါ။
- **အသုံးပြုသူအသစ်\:** plugin ကို ထည့်သွင်းပြီး အောင်မြင်သော အလိုအလျောက် route တစ်ခုကို ရယူပါ။
- **အကဲဖြတ်သူ\:** အခွင့်အာဏာနယ်နိမိတ်နှင့် fail\-closed အပြုအမူကို နားလည်သဘောပေါက်ပါ။
- **ပြန်လည်အသုံးပြုသူ\:** workflow၊ လုံခြုံရေး၊ ဗိသုကာ သို့မဟုတ် CLI အဖြေဆီသို့ တိုက်ရိုက်သွားပါ။
- **ပါဝင်ကူညီသူ သို့မဟုတ် ဘာသာပြန်သူ\:** အဓိကသဘောတူစာချုပ်၊ ဖွံ့ဖြိုးတိုးတက်မှု command များ၊ အကူအညီနှင့် စီမံခန့်ခွဲမှုတို့ကို ရှာဖွေပါ။

## အကြောင်းနှင့်အကျိုး ဆက်စပ်တင်ပြပုံကို သုံးပါ

ဤအစဉ်က လက်တွေ့ကျသော တင်ပြမှုလမ်းကြောင်းကို ပေးသည်\:

- **နောက်ခံ\:** ညွှန်ကြားစာဖြင့် မောင်းနှင်သောအလုပ်သည် လုပ်ပိုင်ခွင့် သို့မဟုတ် အခြေအနေကို သက်သေမပြဘဲ ရည်ရွယ်ချက်ကို ဖော်ပြနိုင်သည်။
- **ပြဿနာအဖုအထစ်\:** ဘေးထွက်သက်ရောက်မှုများက ထိုကွာဟချက်ကို ရလဒ်ပေးပို့ရေးအန္တရာယ်အဖြစ် ပြောင်းလဲစေသည်။
- **ဖြေရှင်းမှု\:** Better Workflows သည် ပန်းတိုင်၊ နယ်ပယ်၊ အထောက်အထား၊ သုံးသပ်မှု၊ လုပ်ဆောင်ချက် နှင့် ဝန်ဆောင်မှုပေးသူနှင့် တိုက်ဆိုင်စစ်ဆေးမှုတို့ကို ချိတ်ဆက်သည်။
- **သက်သေပြချက်\:** ရှင်းလင်းသော အာမခံချက်နှင့် နယ်နိမိတ်များက ဖြေရှင်းမှု မည်သို့အလုပ်လုပ်သည်ကို ပြသည်။
- **လုပ်ဆောင်မှု\:** စာဖတ်သူသည် နက်ရှိုင်းသော အကောင်အထည်ဖော်မှုအသေးစိတ်နှင့် မတွေ့မီ ပထမဆုံးအောင်မြင်မှုကို ရရှိသည်။
- **ဆက်လက်ခရီး\:** အခန်းကဏ္ဍနှင့် ရလဒ်အခြေပြု လမ်းကြောင်းများက သင့်လျော်သော သင်ခန်းစာ၊ လုပ်နည်းလမ်းညွှန်၊ ရှင်းလင်းချက် သို့မဟုတ် ကိုးကားစာသို့ ပို့ဆောင်သည်။

ယာယီသိမ်းဆည်းမှု ပြန်လည်ရယူခြင်း၊ သော့ခတ်မှု၏ပိုင်ဆိုင်ခွင့်၊ ဝန်ဆောင်မှုပေးသူ၏ အချက်အလက်ပို့ဆောင်မှုအဓိပ္ပာယ်အပြည့်အစုံ၊ အမိန့်အားလုံး သို့မဟုတ် အကောင်အထည်ဖော်မှု ပြောင်းလဲသမိုင်းကို မိတ်ဆက်စာမျက်နှာတွင် ထပ်မထည့်ပါနှင့်။ တိုတောင်းသော ဘေးကင်းရေးအဆိုကို ထိုစာမျက်နှာတွင် ထားပြီး စာရင်းစစ်နိုင်သော အသေးစိတ်ကို အတည်ယူရမည့် လမ်းညွှန်တွင် ထားရမည်။

ဤခွဲခြားမှုသည် သင်ခန်းစာ၊ လုပ်နည်းလမ်းညွှန်၊ ရှင်းလင်းချက်နှင့် ကိုးကားစာတို့ကို ခွဲခြားသည့် Diátaxis နည်းလမ်းကို လိုက်နာသည်။ စာမျက်နှာတစ်ခုသည် စာဖတ်သူ၏ လိုအပ်ချက်လေးမျိုးလုံးအတွက် တစ်ပြိုင်နက် အကောင်းဆုံးဖြစ်အောင် မလုပ်နိုင်ပါ။

## ရုပ်ပုံတိုင်းကို ထည့်သင့်သည့်အကြောင်းရှိစေပါ

ဆက်နွယ်မှု၊ အဆင့်ဆင့်ဖွဲ့စည်းပုံ သို့မဟုတ် အခြေအနေပြောင်းလဲမှုကို စာသားထက် သိသိသာသာ ပိုနားလည်လွယ်စေမှ ရုပ်ပုံကို သုံးပါ။

မိတ်ဆက်စာမျက်နှာများတွင် ရုပ်ပုံနှစ်ခုကို ခွင့်ပြုသည်\:

1. **လုပ်ပိုင်ခွင့်နယ်နိမိတ် ဗိသုကာဖွဲ့စည်းပုံ\:** ရည်ရွယ်ချက်၊ လက်ရှိအချက်အလက်၊ ကိရိယာလုပ်ပိုင်ခွင့်၊ ကန့်သတ်ထားသော ထပ်ကြိုးစားမှုနှင့် ဖတ်ရှုရန်သာရှိသော အခြေအနေကို မည်သည့်အလွှာများက သတ်မှတ်သည်ကို ဖြေသည်။
2. **ပန်းတိုင်မှ ပြီးမြောက်မှုအထိ လုပ်ငန်းစက်ဝန်း\:** အထောက်အထားကို ဘယ်မှာစစ်ဆေး၊ ဘေးထွက်သက်ရောက်မှုကို ဘယ်မှာခွင့်ပြုပြီး မသိရသေးသောအခြေအနေက တိုးတက်မှုကို ဘယ်မှာရပ်စေသည်ကို ဖြေသည်။

ရုပ်ပုံတိုင်းတွင် အောက်ပါတို့ ပါရမည်\:

- တိုတောင်း၍ အဓိပ္ပာယ်ရှိသော အစားထိုးစာသား\;
- ရုပ်ပုံကို ဖျောက်ထားလျှင် သို့မဟုတ် Mermaid မဖော်ပြနိုင်လျှင် ကောက်ချက်ကို ထိန်းသိမ်းပေးသည့် ကပ်လျက်တည်ရှိသော အဓိပ္ပာယ်တူစာသား\;
- ဖြစ်နိုင်သမျှ အရေးကြီးတံဆိပ်စာများအတွက် စာသားအစစ်\;
- ရုပ်ပုံကို လက်ရှိနှင့်ကိုက်ညီအောင် ထိန်းသိမ်းရန် အကြောင်းပြပေးသော ရေရှည်တည်တံ့သည့် စာဖတ်သူမေးခွန်း။

အလှဆင်မျက်နှာပြင်ပုံများ၊ စာသားများလွန်းသောပုံများ သို့မဟုတ် စာရင်းတိုတစ်ခုကိုသာ ထပ်ဖော်ပြသောပုံကြမ်း မထည့်ပါနှင့်။ ရွေးချယ်မှုဇယားများကို တိုတောင်းသော ကော်လံနှစ်ခုသာထား၍ ကျဉ်းသောမျက်နှာပြင်ပေါ်တွင်လည်း အသုံးပြုနိုင်စေပါ။

## ဘာသာစကားများအကြား အဓိပ္ပာယ်ကို ထိန်းသိမ်းပါ

အင်္ဂလိပ်သည် အဓိပ္ပာယ်ကိုးကားမူဖြစ်ပြီး လိုက်မီရမည့် လိုင်းအရေအတွက် မဟုတ်ပါ။ တရုတ်ရိုးရာစာ၊ တရုတ်ရိုးရှင်းစာ၊ ဂျပန်နှင့် ကိုရီးယားတို့သည် တူညီသော သဘောတူသတ်မှတ်ချက်ကို ထိန်းသိမ်းလျက် မိခင်ဘာသာစကားဖတ်သူအတွက် သဘာဝကျသင့်သည်။

အောက်ပါအရာများသည် တူညီသောအဓိပ္ပာယ်ကို ဆက်လက်ထိန်းသိမ်းရမည်\:

- အဓိပ္ပာယ်အပိုင်းရှစ်ပိုင်းနှင့် ၎င်းတို့၏အစဉ်\;
- ပထမဆုံးအောင်မြင်မှုအတွက် အမိန့်များနှင့် ထုတ်ကုန်သတ်မှတ်အမှတ်များ\;
- လုပ်ပိုင်ခွင့်၊ အထောက်အထား၊ မသိရသေးသောအခြေအနေ၊ ညွှန်ကြားစာနှင့် ကိုယ်ရေးကိုယ်တာလုံခြုံမှုဆိုင်ရာ အဆိုငါးခု\;
- လုပ်ငန်းစီးဆင်းမှု၊ လုံခြုံရေး၊ ဗိသုကာဖွဲ့စည်းပုံ၊ CLI၊ အကူအညီ၊ စီမံအုပ်ချုပ်မှု၊ ဖွံ့ဖြိုးရေးနှင့် လိုင်စင်ဆိုင်ရာ သွားရောက်ရမည့်နေရာများ\;
- ရုပ်ပုံရည်ရွယ်ချက်၊ လုပ်ငန်းစက်ဝန်းအဆင့်များနှင့် အရန်စာသားများ\;
- ဗားရှင်းရင်းမြစ်နှင့် တံဆိပ်မူဝါဒ။

ခေါင်းစဉ်၊ ဝါကျခွဲပုံ၊ ပုဒ်ဖြတ်ပုဒ်ရပ်၊ နမူနာနှင့် လုပ်ဆောင်ရန်ဖိတ်ခေါ်ချက်များကို ဘာသာစကားအလိုက် သဘာဝကျစေနိုင်သည်။ အမိန့်များ၊ ရွေးချယ်ကိရိယာများ၊ အထောက်အထားသတ်မှတ်အမှတ်များ သို့မဟုတ် လုံခြုံရေးဆိုင်ရာ အဓိပ္ပာယ်သတ်မှတ်ချက်များကို ဘယ်တော့မှ ဘာသာမပြန်ပါနှင့်။

## အမြန်ဖတ်ရှုခြင်းနှင့် ဘာသာပြန်ခြင်းအတွက် ရေးသားပါ

- စာဖတ်သူရမည့် ရလဒ်ဖြင့် စတင်ပြီး အရေးကြီးဝေါဟာရများကို ခေါင်းစဉ်နှင့် စာပိုဒ်အစတွင် ထားပါ။
- ပြုသူကိုဖော်ပြသော ဝါကျပုံစံသုံးပြီး လုပ်ဆောင်ချက်အတွက် တာဝန်ရှိသူကို အမည်တပ်ပါ။
- လုပ်ထုံးလုပ်နည်းများတွင် စာဖတ်သူကို တိုက်ရိုက်ပြောပါ။
- စာပိုဒ်များကို တိုစေပြီး တစ်ပိုဒ်လျှင် တာဝန်တစ်ခုသာ ပေးပါ။
- အစဉ်လိုက်အတွက် နံပါတ်စဉ်စာရင်း၊ အစဉ်မလိုသော ရွေးချယ်စရာများအတွက် အမှတ်ပြစာရင်း သုံးပါ။
- “ဤနေရာကိုနှိပ်ပါ” ကဲ့သို့ ယေဘုယျစာအစား ဖော်ပြချက်ပါသော လင့်ခ်များ သုံးပါ။
- ခေါင်းစဉ်များကို အဆင့်ဆင့်၊ တိကျပြီး တစ်ဆင့်တည်းတွင် ပုံစံတူထားပါ။
- ဘာသာပြန်သော်လည်း အဓိပ္ပာယ်မပျောက်သည့် တိုက်ရိုက်၍ မရှုပ်ထွေးသော ဘာသာစကားကို ဦးစားပေးပါ။
- အခြေအနေသတ်မှတ်ချက်ကို ညွှန်ကြားချက်မတိုင်မီ၊ မျှော်လင့်ရလဒ်ကို အမိန့်နောက်တွင် ထားပါ။

## အလှဆင်မှုမဟုတ်ဘဲ အဓိပ္ပာယ်ကို အတည်ပြုစစ်ဆေးပါ

စာတမ်းစမ်းသပ်မှုများသည် ခေါင်းစဉ်ကိုက်ညီမှုထက် ပို၍စစ်ဆေးနိုင်ရမည်။ ၎င်းတို့ စစ်ဆေးသည်မှာ\:

- H1 တစ်ခုနှင့် ယုတ္တိကျသော ခေါင်းစဉ်အဆင့်ဆင့်ခွဲခြားမှု၊
- အစဉ်လိုက် semantic ကဏ္ဍနှင့် အဓိကဖော်ပြချက် အမှတ်အသားများ၊
- အတိအကျ ပထမဆုံးအောင်မြင်မှု command များနှင့် တည်ငြိမ်သော identifier များ၊
- နှိုင်းရလင့်ခ်များနှင့် ဘာသာစကားအလိုက် အသေးစိတ်လမ်းကြောင်းများ၊
- runtime metadata နှင့် ကိုက်ညီသော version badge၊
- အဓိပ္ပာယ်ရှိသော ပုံ alt စာသားနှင့် ကပ်လျက်ရှိသော visual fallback များ၊
- ပြည့်စုံသော စာသားနှင့် ညီမျှသည့် Mermaid သက်တမ်းစက်ဝန်း တစ်ခုတည်း၊
- ကော်လံနှစ်ခု ဇယားနှင့် စာပိုဒ်အရှည် ကန့်သတ်ချက်များ၊
- landing page များမှ သတ်မှတ်ထားသော အတွင်းပိုင်း အသေးစိတ်ဖော်ပြချက်များ ကင်းမဲ့ခြင်း၊
