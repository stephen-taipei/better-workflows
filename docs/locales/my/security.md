အဆိုပြုထားသည့် တစ်ခုတည်းသော အထောက်အထားရင်းမြစ်တွင် ကိုယ်ရေးကိုယ်တာမှတ်တမ်း သို့မဟုတ် ထိခိုက်လွယ်သော လုပ်ငန်းဆောင်ရွက်မှုဆိုင်ရာ အကြောင်းအရာပါဝင်ပြီး ထိခိုက်လွယ်သော အချက်အလက်များကို ဖယ်ရှားဖုံးကွယ်၍ မရနိုင်ပါက ထိုရင်းမြစ်ကို မစုဆောင်းပါနှင့်၊ မပေးပို့ပါနှင့်။ ထိခိုက်လွယ်သော အချက်အလက်များကို ဖယ်ရှားဖုံးကွယ်ထားသည့် `REJECTED_WITH_EVIDENCE` အကြောင်းပြချက်ကိုသာ မှတ်တမ်းတင်ပါ။

## ပံ့ပိုးပေးသော ဗားရှင်းများ

| ဗားရှင်း | ပံ့ပိုးမှု |
| --- | --- |
| နောက်ဆုံးထုတ်ဝေထားသော ဖြန့်ချိဗားရှင်းနှင့် ပြောင်းလဲ၍မရသော Codex တည်ဆောက်ဗားရှင်း | ပံ့ပိုးပေးသည် |
| ယခင် ပြောင်းလဲ၍မရသော ကက်ရှ်ဗားရှင်းများ | ယခင်ဗားရှင်းသို့ ပြန်ပြောင်းရန် ရည်ရွယ်ထားသည်။ အတိအလင်း ကြေညာထားခြင်းမရှိလျှင် ပြင်ဆင်ချက်များကို ဗားရှင်းအဟောင်းများသို့ ပြန်လည်ထည့်သွင်းမပေးပါ |
| မဖြန့်ချိရသေးသော သီးခြားခွဲထုတ်မူများ သို့မဟုတ် ပြုပြင်ထားသော ကက်ရှ်အကြောင်းအရာများ | ပံ့ပိုးမပေးပါ |

## လုံခြုံရေးအားနည်းချက်ကို အစီရင်ခံခြင်း

ကျေးဇူးပြု၍ [GitHub ၏ သီးသန့်လုံခြုံရေးအားနည်းချက် အစီရင်ခံစနစ်](https://github.com/stephen-taipei/better-workflows/security/advisories/new) ကို အသုံးပြုပါ။ သံသယရှိသော လုံခြုံရေးအားနည်းချက်အတွက် အများမြင်နိုင်သော ပြဿနာတင်ပြချက် မဖွင့်ပါနှင့်။

အောက်ပါတို့ကို ထည့်သွင်းပါ\:

- ထိခိုက်သော ဗားရှင်းနှင့် ပလပ်အင်တည်ဆောက်ဗားရှင်း\;
- ပတ်ဝန်းကျင်နှင့် Node\.js ဗားရှင်း\;
- ပြဿနာကို ပြန်လည်ဖြစ်ပေါ်စေရန် အနည်းဆုံးလိုအပ်သော အဆင့်များ\;
- မျှော်မှန်းထားသော လုံခြုံရေးနယ်နိမိတ်နှင့် လက်တွေ့တွေ့ရှိသော လုံခြုံရေးနယ်နိမိတ်\;
- သက်ရောက်မှုနှင့် သိရှိထားသော ယာယီဖြေရှင်းနည်းများ\;
- အစီရင်ခံစာတွင် လျှို့ဝှက်အကြောင်းအရာ ပါဝင်ခြင်းရှိမရှိ။

လက်ရှိအသုံးပြုနိုင်သော အထောက်အထားစိစစ်ရေးအချက်အလက်များ၊ လက်မှတ်ရေးထိုးသော့များ၊ ဝန်ဆောင်မှုပေးသူ၏ တိုကင်များ၊ မော်ဒယ်သို့ ထည့်သွင်းပေးသော သီးသန့်အကြောင်းအရာများ၏ မပြုပြင်ရသေးသော မူရင်းများ သို့မဟုတ် တတိယပါတီ၏ ကိုယ်ရေးအချက်အလက်များကို မထည့်သွင်းပါနှင့်။

## တုံ့ပြန်မှု

စီမံထိန်းသိမ်းသူသည် အသုံးချဆောင်ရွက်နိုင်သော အစီရင်ခံစာကို လက်ခံရရှိကြောင်း အတည်ပြုပြီး ၎င်း၏အကျုံးဝင်မှုကို စိစစ်ကာ ပြုပြင်ဖြေရှင်းခြင်းနှင့် ထုတ်ဖော်အသိပေးခြင်းကို ညှိနှိုင်းဆောင်ရွက်မည်။ ပုံသေတုံ့ပြန်ချိန်ပါသော SLA ကို ကတိမပေးပါ။ မသိရှိရသေးသော သို့မဟုတ် တိုက်ဆိုင်ညှိနှိုင်းစစ်ဆေး၍ မပြီးသေးသော ရလဒ်များကို ဆက်လက်ပိတ်ထားပြီး အတည်မပြုရသေးလျှင် ဆက်လက်ဆောင်ရွက်ခြင်းကို ငြင်းပယ်မည်။

## လုံခြုံရေးနယ်နိမိတ်များ

Better Workflows သည် ယုံကြည်စိတ်ချရသော စက်တွင်းကုဒ်သိုလှောင်ရာ၊ လုပ်ဆောင်ပေးသည့်စက်နှင့် အကောင်အထည်ဖော်အသုံးပြုနိုင်သော ကိရိယာအစုံ ရှိသည်ဟု ယူဆထားသည်။ Node ၏ ခွင့်ပြုချက်ပုံစံသည် အလွှာဆင့်ကာကွယ်ရေးဖြစ်ပြီး အန္တရာယ်ရှိသောကုဒ်အတွက် လည်ပတ်မှုစနစ်အဆင့် သီးခြားကန့်သတ်ပတ်ဝန်းကျင် မဟုတ်ပါ။ ပြည့်စုံသော [လုံခြုံရေးလမ်းညွှန်](security-guide.md) ကို ကြည့်ပါ။
