[ພາບລວມໃນ 41 ສະບັບປັບເຂົ້າທ້ອງຖິ່ນ ແລະ ຊ່ອງທາງເຂົ້າເວັບທາງການ](../../../docs/LANGUAGES.md)\. ສະບັບພາສາອັງກິດຂອງນະໂຍບາຍຄວາມປອດໄພທີ່ກຳນົດຂໍ້ບັງຄັບນີ້ ຍັງຄົງເປັນຕົ້ນສະບັບອ້າງອີງທີ່ມີອຳນາດຊີ້ຂາດ\.

ຖ້າແຫຼ່ງຫຼັກຖານພຽງແຫຼ່ງດຽວທີ່ສະເໜີມີປະຫວັດສ່ວນຕົວ ຫຼືເນື້ອຫາ ການດຳເນີນງານທີ່ອ່ອນໄຫວ ເຊິ່ງບໍ່ສາມາດລຶບຫຼືປິດບັງຂໍ້ມູນອ່ອນໄຫວໄດ້\, ຫ້າມເກັບຮວບຮວມຫຼືສົ່ງຂໍ້ມູນນັ້ນ\. ບັນທຶກພຽງເຫດຜົນ `REJECTED_WITH_EVIDENCE` ທີ່ລຶບຫຼືປິດບັງຂໍ້ມູນອ່ອນໄຫວແລ້ວເທົ່ານັ້ນ\.

## ລາຍງານຊ່ອງໂຫວ່

ກະລຸນາໃຊ້ [ການລາຍງານຊ່ອງໂຫວ່ແບບສ່ວນຕົວຂອງ GitHub](https://github.com/stephen-taipei/better-workflows/security/advisories/new)\. ຫ້າມເປີດປະເດັນສາທາລະນະສຳລັບຊ່ອງໂຫວ່ທີ່ສົງໄສ\.

ໃຫ້ລະບຸ\:

- ເວີຊັນ ແລະບິວປລັກອິນທີ່ໄດ້ຮັບຜົນກະທົບ\;
- ສະພາບແວດລ້ອມ ແລະເວີຊັນ Node\.js\;
- ຂັ້ນຕອນຂັ້ນຕ່ຳທີ່ຈຳເປັນເພື່ອເຮັດໃຫ້ບັນຫາເກີດຂຶ້ນຊ້ຳ\;
- ຂອບເຂດຄວາມປອດໄພທີ່ຄາດໄວ້ ແລະທີ່ສັງເກດເຫັນ\;
- ຜົນກະທົບ ແລະວິທີແກ້ໄຂຊົ່ວຄາວທີ່ຮູ້\;
- ວ່າລາຍງານມີເນື້ອຫາລັບຫຼືບໍ່\.

ຫ້າມໃສ່ຂໍ້ມູນຢືນຢັນຕົວຕົນທີ່ຍັງໃຊ້ງານໄດ້\, ກະແຈລົງລາຍເຊັນ\, ໂທເຄັນຂອງຜູ້ໃຫ້ບໍລິການ\, ເນື້ອຫາສ່ວນຕົວສະບັບດິບ ທີ່ປ້ອນໃຫ້ແບບຈຳລອງ ຫຼືຂໍ້ມູນສ່ວນບຸກຄົນຂອງບຸກຄົນທີສາມ\.

## ການຕອບກັບ

ຜູ້ດູແລໂຄງການຈະຢືນຢັນການຮັບລາຍງານທີ່ສາມາດນຳໄປດຳເນີນການໄດ້\, ກວດສອບຂອບເຂດຂອງລາຍງານ ແລະ ປະສານງານການແກ້ໄຂກັບການເປີດເຜີຍ\. ບໍ່ມີການສັນຍາ SLA ທີ່ກຳນົດເວລາຕອບກັບຕາຍຕົວ\. ຜົນລັບທີ່ຍັງບໍ່ຮູ້ ຫຼືຍັງບໍ່ໄດ້ກວດທຽບໃຫ້ສອດຄ່ອງກັນ ຈະຍັງຄົງຖືກປິດກັ້ນ ໂດຍປະຕິເສດການດຳເນີນການຕໍ່ເມື່ອຍັງບໍ່ໄດ້ຢືນຢັນ\.

## ຂອບເຂດຄວາມປອດໄພ

Better Workflows ຕັ້ງຢູ່ບົນສົມມຸດຖານວ່າ ຄັງລະຫັດພາຍໃນເຄື່ອງ\, ເຄື່ອງທີ່ໃຊ້ເຮັດວຽກ ແລະຊຸດເຄື່ອງມືທີ່ປະຕິບັດງານໄດ້ ເປັນສິ່ງທີ່ເຊື່ອຖືໄດ້\. ຮູບແບບການອະນຸຍາດຂອງ Node ເປັນການປ້ອງກັນຫຼາຍຊັ້ນ ແລະບໍ່ແມ່ນສະພາບແວດລ້ອມແຍກຈຳກັດຂອງລະບົບປະຕິບັດການ ສຳລັບລະຫັດອັນຕະລາຍ\. ເບິ່ງ [ຄູ່ມືຄວາມປອດໄພ](security-guide.md) ສະບັບຄົບຖ້ວນ\.
