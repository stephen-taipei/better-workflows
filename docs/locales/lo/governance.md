Better Workflows ນຳພາໂດຍຜູ້ດູແລໂຄງການ\.

## ຮູບແບບການຕັດສິນໃຈ

- ຜູ້ດູແລໂຄງການຍອມຮັບຫຼືປະຕິເສດການປ່ຽນແປງດ້ານການອອກແບບ ແລະການເຜີຍແຜ່ໃນລະດັບໂຄງການ\.
- ພິຈາລະນາຫຼັກຖານ\, ການທົດສອບທີ່ເຮັດຊ້ຳໄດ້\, ຂອບເຂດຄວາມປອດໄພ\, ຄວາມເຂົ້າກັນໄດ້ ແລະ ຄ່າໃຊ້ຈ່າຍໃນການບຳລຸງຮັກສາ ກ່ອນຄວາມນິຍົມຫຼືການລົງຄະແນນສຽງຂ້າງຫຼາຍ\.
- ການປ່ຽນແປງຂໍ້ຕົກລົງສາທາລະນະ ແລະຂອບເຂດຄວາມປອດໄພ ຕ້ອງຜ່ານການກວດທານຢ່າງຊັດເຈນ\.
- ຂໍ້ສະເໜີທີ່ຖືກປະຕິເສດອາດຖືກພິຈາລະນາຄືນ ເມື່ອຫຼັກຖານໃໝ່ປ່ຽນແປງ ການຊັ່ງນ້ຳໜັກຂໍ້ໄດ້ຂໍ້ເສຍ\.

## ອຳນາດໃນຂັ້ນຕອນການເຮັດວຽກ

ພາຍໃນການຮັນ Better Workflows\, Root ເປັນອຳນາດດຽວໃນການປ່ຽນແປງ ແລະຍອມຮັບ ຄວາມສ່ຽງ\. ກົດລະບຽບ runtime ນີ້ບໍ່ໄດ້ມອບກຳມະສິດ repository ຫຼື ແທນທີ່ສິດອະນຸຍາດຂອງ GitHub\.

## ການເຜີຍແຜ່ລຸ້ນ

ບິວແຄຊປລັກອິນປ່ຽນແປງບໍ່ໄດ້\. ລຸ້ນທີ່ກຽມເປັນຕົວເລືອກເພື່ອເຜີຍແຜ່ຕ້ອງຜ່ານດ່ານກວດທີ່ນຳໃຊ້ກ່ຽວກັບ ການທົດສອບ\, ການປະເມີນ\, ຄວາມທັນເວລາຂອງຫຼັກຖານ\, ຫຼັກຖານ\, ສາຂາທີ່ມີການປ້ອງກັນ ແລະການກວດທຽບ ຕົ້ນສະບັບ\/ແຄຊໃຫ້ສອດຄ່ອງກັນ ກ່ອນເຜີຍແຜ່\.

## ການປ່ຽນແປງການກຳກັບດູແລ

ການປ່ຽນແປງການກຳກັບດູແລຈະຖືກກວດທານເປັນການປ່ຽນແປງຂໍ້ຕົກລົງສາທາລະນະ ແລະຕ້ອງບັນທຶກ ໄວ້ໃນປະຫວັດຄັງລະຫັດ\.
