README ຂອງ Better Workflows ເປັນໜ້າແນະນຳ\, ບໍ່ແມ່ນຄູ່ມືອ້າງອີງທີ່ຫຍໍ້ລວມໄວ້\. ໜ້າທີ່ຂອງມັນຄືຊ່ວຍໃຫ້ຜູ້ອ່ານຕອບຄຳຖາມຫ້າຂໍ້ຕາມລຳດັບ\:

1. ສິ່ງນີ້ແມ່ນຫຍັງ ແລະ ເໝາະກັບຂ້ອຍບໍ\?
2. ມັນແກ້ບັນຫາຫຍັງ\?
3. ເປັນຫຍັງຂ້ອຍຈຶ່ງຄວນເຊື່ອຄຳກ່າວອ້າງຂອງມັນ\?
4. ເສັ້ນທາງທີ່ສັ້ນທີ່ສຸດສູ່ຄວາມສຳເລັດຄັ້ງທຳອິດແມ່ນຫຍັງ\?
5. ຂ້ອຍຄວນໄປບ່ອນໃດຕໍ່\?

ແຜນແມ່ບົດນີ້ກຳນົດຂໍ້ຕົກລົງດ້ານການເລົ່າເລື່ອງ\, ພາບປະກອບ\, ການປັບເຂົ້າທ້ອງຖິ່ນ ແລະ ການກວດຢືນຢັນສຳລັບ README ທຸກໄຟລ໌ໃນຄັງລະຫັດ\. ແຫຼ່ງຂໍ້ມູນທີ່ເຄື່ອງອ່ານໄດ້ແມ່ນ [`readme-quality-v1.json`](../../../plugins/better-workflows/config/readme-quality-v1.json)\.

## ເລີ່ມຈາກການຕັດສິນໃຈຂອງຜູ້ອ່ານ

GitHub ສະແດງ README ກ່ອນເນື້ອຫາສ່ວນໃຫຍ່ໃນຄັງລະຫັດ\. ດັ່ງນັ້ນ ໜ້າຈໍທຳອິດຕ້ອງລະບຸຄຳໝັ້ນຂອງຜະລິດຕະພັນ\, ກຸ່ມເປົ້າໝາຍ ແລະ ການກະທຳຖັດໄປທີ່ມີຂອບເຂດຊັດເຈນ\. ຕ້ອງບໍ່ເລີ່ມດ້ວຍສະຖາປັດຕະຍະກຳພາຍໃນ\, ຄູ່ມືອ້າງອີງຄຳສັ່ງສະບັບເຕັມ ຫຼື ລາຍລະອຽດການກູ້ຄືນລຸ້ນເຜີຍແຜ່\.

ຂຽນເພື່ອຮອງຮັບວຽກທີ່ຜູ້ອ່ານຕ້ອງການເຮັດຕໍ່ໄປນີ້\:

- **ຜູ້ເຂົ້າມາໃໝ່\:** ຕັດສິນໃຈໄດ້ຢ່າງວ່ອງໄວວ່າ Better Workflows ແກ້ໄຂບັນຫາທີ່ກ່ຽວຂ້ອງ ຫຼືບໍ່\.
- **ຜູ້ໃຊ້ໃໝ່\:** ຕິດຕັ້ງ plugin ແລະບັນລຸເສັ້ນທາງອັດຕະໂນມັດທີ່ສຳເລັດໜຶ່ງຄັ້ງ\.
- **ຜູ້ປະເມີນ\:** ເຂົ້າໃຈຂອບເຂດອຳນາດ ແລະພຶດຕິກຳແບບ fail\-closed\.
- **ຜູ້ດຳເນີນງານທີ່ກັບມາ\:** ຂ້າມໄປຫາຄຳຕອບກ່ຽວກັບ workflow\, ຄວາມປອດໄພ\, ສະຖາປັດຕະຍະກຳ\, ຫຼື CLI ໄດ້ທັນທີ\.
- **ຜູ້ປະກອບສ່ວນ ຫຼື ຜູ້ແປ\:** ຊອກຫາ canonical contract\, ຄຳສັ່ງການພັດທະນາ\, ການສະໜັບສະໜູນ\, ແລະການຄຸ້ມຄອງ\.

ຢ່າເຮັດຊ້ຳເນື້ອຫາການກູ້ຄືນແຄຊ\, ຄວາມເປັນເຈົ້າຂອງການລັອກ\, ຄວາມໝາຍຂອງການຮັບສົ່ງຂໍ້ມູນກັບຜູ້ໃຫ້ບໍລິການທັງໝົດ\, ລາຍການຄຳສັ່ງຄົບຊຸດ ຫຼື ປະຫວັດການປ່ຽນແປງການພັດທະນາໃນໜ້າແນະນຳ\. ຄຳກ່າວອ້າງດ້ານຄວາມປອດໄພແບບກະຊັບຢູ່ໃນໜ້ານັ້ນ\; ລາຍລະອຽດທີ່ກວດສອບຍ້ອນຫຼັງໄດ້ຕ້ອງຢູ່ໃນຄູ່ມືມາດຕະຖານ\.

ການແຍກນີ້ເປັນໄປຕາມ Diátaxis ທີ່ແຍກບົດຮຽນ\, ຄູ່ມືປະຕິບັດ\, ຄຳອະທິບາຍ ແລະ ເອກະສານອ້າງອີງ\. ໜ້າດຽວບໍ່ສາມາດຕອບສະໜອງຄວາມຕ້ອງການທັງສີ່ແບບໃຫ້ດີທີ່ສຸດພ້ອມກັນ\.

## ພາບປະກອບທຸກຊິ້ນຕ້ອງມີເຫດຜົນຮອງຮັບ

ໃຊ້ພາບປະກອບສະເພາະເມື່ອມັນເຮັດໃຫ້ເຂົ້າໃຈຄວາມສຳພັນ\, ລຳດັບຊັ້ນ ຫຼື ການປ່ຽນສະຖານະໄດ້ງ່າຍກວ່າຂໍ້ຄວາມຢ່າງຊັດເຈນ\.

ໜ້າແນະນຳອະນຸຍາດໃຫ້ມີພາບປະກອບສອງຊິ້ນ\:

1. **ສະຖາປັດຕະຍະກຳຂອບເຂດອຳນາດ\:** ຕອບວ່າຊັ້ນໃດກຳນົດເຈດຕະນາ\, ຂໍ້ເທັດຈິງປັດຈຸບັນ\, ອຳນາດຂອງເຄື່ອງມື\, ການລອງໃໝ່ທີ່ມີຂອບເຂດ ແລະ ສະຖານະທີ່ອ່ານໄດ້ຢ່າງດຽວ\.
2. **ວົງຈອນຈາກເປົ້າໝາຍຈົນສຳເລັດ\:** ຕອບວ່າກວດຫຼັກຖານຢູ່ໃສ\, ອະນຸຍາດຜົນຂ້າງຄຽງຢູ່ໃສ ແລະ ສະຖານະທີ່ຍັງບໍ່ຮູ້ຢຸດຄວາມຄືບໜ້າຢູ່ໃສ\.

ພາບປະກອບທຸກຊິ້ນຕ້ອງມີ\:

- ຂໍ້ຄວາມທົດແທນທີ່ກະຊັບ ແລະ ມີຄວາມໝາຍ\;
- ຂໍ້ຄວາມທຽບເທົ່າຢູ່ຂ້າງກັນທີ່ຮັກສາຂໍ້ສະຫຼຸບເມື່ອພາບຖືກເຊື່ອງ ຫຼື Mermaid ບໍ່ສະແດງຜົນ\;
- ຂໍ້ຄວາມຈິງສຳລັບປ້າຍກຳກັບສຳຄັນເມື່ອເຮັດໄດ້\;
- ຄຳຖາມຂອງຜູ້ອ່ານທີ່ຍັງໃຊ້ໄດ້ໃນໄລຍະຍາວ ແລະ ເປັນເຫດຜົນໃຫ້ຮັກສາພາບໃຫ້ທັນປັດຈຸບັນ\.

ຢ່າເພີ່ມພາບໜ້າຈໍເພື່ອຕົບແຕ່ງ\, ພາບທີ່ມີຂໍ້ຄວາມໜາແໜ້ນ ຫຼື ແຜນພາບທີ່ພຽງເຮັດຊ້ຳລາຍການສັ້ນ\. ໃຫ້ຕາຕະລາງຕົວເລືອກມີສອງຖັນທີ່ກະຊັບ ເພື່ອໃຫ້ຍັງໃຊ້ໄດ້ໃນໜ້າຈໍແຄບ\.

## ຮັກສາຄວາມໝາຍຂ້າມພາສາ

ພາສາອັງກິດເປັນແຫຼ່ງອ້າງອີງຄວາມໝາຍ\, ບໍ່ແມ່ນເປົ້າໝາຍຈຳນວນແຖວ\. ພາສາຈີນຕົວເຕັມ\, ຈີນຕົວຫຍໍ້\, ຍີ່ປຸ່ນ ແລະ ເກົາຫຼີຄວນອ່ານເປັນທຳມະຊາດສຳລັບເຈົ້າຂອງພາສາ ໂດຍຮັກສາຂໍ້ຕົກລົງດຽວກັນ\.

ລາຍການຕໍ່ໄປນີ້ຕ້ອງມີຄວາມໝາຍທຽບເທົ່າກັນ\:

- ແປດສ່ວນຄວາມໝາຍ ແລະ ລຳດັບຂອງມັນ\;
- ຄຳສັ່ງສຳລັບຄວາມສຳເລັດຄັ້ງທຳອິດ ແລະ ຕົວລະບຸຜະລິດຕະພັນ\;
- ຄຳກ່າວອ້າງຫ້າຂໍ້ເລື່ອງອຳນາດ\, ຫຼັກຖານ\, ສະຖານະທີ່ຍັງບໍ່ຮູ້\, ຂໍ້ຄວາມສັ່ງ ແລະ ຄວາມເປັນສ່ວນຕົວ\;
- ປາຍທາງຂອງຂັ້ນຕອນການເຮັດວຽກ\, ຄວາມປອດໄພ\, ສະຖາປັດຕະຍະກຳ\, CLI\, ການຊ່ວຍເຫຼືອ\, ການກຳກັບດູແລ\, ການພັດທະນາ ແລະ ໃບອະນຸຍາດ\;
- ຈຸດປະສົງຂອງພາບ\, ໄລຍະຂອງວົງຈອນຊີວິດ ແລະ ຂໍ້ຄວາມສຳຮອງ\;
- ແຫຼ່ງທີ່ມາຂອງລຸ້ນ ແລະ ນະໂຍບາຍປ້າຍສະຖານະ\.

ຫົວຂໍ້\, ການແບ່ງປະໂຫຍກ\, ເຄື່ອງໝາຍວັກຕອນ\, ຕົວຢ່າງ ແລະ ຂໍ້ຄວາມຊັກຊວນໃຫ້ລົງມື ອາດປັບໃຫ້ເປັນທຳມະຊາດໄດ້\. ຫ້າມແປຄຳສັ່ງ\, ຕົວເລືອກ\, ຕົວລະບຸຫຼັກຖານ ຫຼື ຄວາມໝາຍດ້ານຄວາມປອດໄພ\.

## ຂຽນໃຫ້ອ່ານກວາດສາຍຕາ ແລະ ແປໄດ້ງ່າຍ

- ເລີ່ມດ້ວຍຜົນລັບຂອງຜູ້ອ່ານ ແລະ ວາງຄຳສຳຄັນໄວ້ຕົ້ນ ຫົວຂໍ້ ແລະ ຫຍໍ້ໜ້າ\.
- ໃຊ້ປະໂຫຍກທີ່ລະບຸຜູ້ກະທຳ ແລະ ບອກວ່າໃຜຮັບຜິດຊອບການກະທຳນັ້ນ\.
- ເວົ້າກັບຜູ້ອ່ານໂດຍກົງເມື່ອອະທິບາຍຂັ້ນຕອນປະຕິບັດ\.
- ຂຽນຫຍໍ້ໜ້າໃຫ້ສັ້ນ ແລະ ໃຫ້ແຕ່ລະຫຍໍ້ໜ້າເຮັດໜ້າທີ່ດຽວ\.
- ໃຊ້ລາຍການລຳດັບເລກສຳລັບລຳດັບຂັ້ນ ແລະ ລາຍການຫົວຂໍ້ຍ່ອຍສຳລັບຕົວເລືອກທີ່ບໍ່ຕ້ອງຮຽງລຳດັບ\.
- ໃຊ້ລິ້ງທີ່ອະທິບາຍປາຍທາງ ແທນປ້າຍທົ່ວໄປເຊັ່ນ “ກົດທີ່ນີ້”\.
- ໃຫ້ຫົວຂໍ້ມີລຳດັບຊັ້ນ\, ສະເພາະເຈາະຈົງ ແລະ ໃຊ້ຮູບແບບຄູ່ຂະໜານໃນລະດັບດຽວກັນ\.
- ເລືອກພາສາທີ່ກົງຄວາມໝາຍ\, ບໍ່ກຳກວມ ແລະ ຍັງຮັກສາຄວາມໝາຍເມື່ອແປ\.
- ວາງເງື່ອນໄຂກ່ອນຄຳແນະນຳ ແລະ ຜົນທີ່ຄາດຫວັງຫຼັງຄຳສັ່ງ\.

## ກວດຢືນຢັນຄວາມໝາຍ ບໍ່ແມ່ນການຕົບແຕ່ງ

ການທົດສອບເອກະສານຕ້ອງກວດພົບໄດ້ຫຼາຍກວ່າການທີ່ຫົວຂໍ້ກົງກັນ\. ມັນກວດຢືນຢັນ\:

- ສ່ວນ semantic ທີ່ຈັດລຳດັບ ແລະຕົວໝາຍ critical\-claim\;

- ລິ້ງແບບ relative ແລະປາຍທາງລາຍລະອຽດສະເພາະແຕ່ລະພາສາ\;

- ຂໍ້ຄວາມ alt ຂອງຮູບພາບທີ່ມີຄວາມໝາຍ ແລະ visual fallback ທີ່ຢູ່ຕິດກັນ\;
- Mermaid lifecycle ດຽວພ້ອມຂໍ້ຄວາມທຽບເທົ່າທີ່ສົມບູນ\;
- ຕາຕະລາງສອງຖັນ ແລະງົບປະມານຄວາມຍາວຂອງວັກ\;
