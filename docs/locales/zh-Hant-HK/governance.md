Better Workflows 由維護者主導。

## 決策模式

- 維護者接受或拒絕專案層面的設計及版本發佈變更。
- 證據、可重現的測試、安全邊界、相容性及維護成本，會優先於受歡迎程度或多數票結果作考慮。
- 公開契約及保安邊界的變更須經明確審閱。
- 如新證據改變了利弊取捨，已被拒絕的提案可獲重新考慮。

## 工作流程權限

喺 Better Workflows 執行期間，Root 係唯一具備變更同風險承擔權力嘅角色。此 runtime 規則唔會授予代碼庫擁有權，亦唔會覆蓋 GitHub 權限。

## 版本發佈

外掛快取建置版本不可變更。候選發佈版本必須在發佈前通過適用的測試、評估、證據時效性、證據、受保護分支，以及來源／快取核對關卡。

## 管治變更

管治變更須按公開契約變更的方式審閱，並必須記錄在儲存庫歷史紀錄中。
