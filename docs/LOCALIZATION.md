# Better Workflows localization policy

[Language index](LANGUAGES.md) | [Canonical English README](../README.md) | [Official website](https://betterworkflows.dev/)

V5.0.rc1 covers `en` and `zh-Hant-TW`. Its planned website and documentation include five pages per locale. The other 39 locale editions remain in private development for V5.0.rc2; they are not RC1 public routes or prerequisites. Planned routes and locally generated files are not publication receipts.

## Meaning before literal translation

The implementation uses `fresh` as shorthand for evidence that is still valid for the declared source, revision, screen, or provider state. It does not imply real-time data or food-like freshness. Taiwan Traditional Chinese uses **證據時效性** for evidence freshness, **來源綁定** for source binding, **provider 狀態核對** for provider reconciliation, and **影響範圍** for blast radius.

CLI commands, the `auto` template ID, evidence kinds, JSON keys, filenames, code symbols, Git references, and normative security conditions remain exact English identifiers. Explanatory prose is localized. English is canonical for implementation and security contracts; translations must preserve authority, fail-closed behavior, reconciliation, and completion semantics.

## RC1 source and generation

The public RC1 source contains the bilingual catalogs in `docs/rc1-catalogs/`. The website and generated Markdown pages use only `en` and `zh-Hant-TW`. `docs/LANGUAGES.md` lists the two planned locale routes. The RC1 public entrypoint and template are `auto`; its public policies are `read-only-v1`, `code-change-v1`, and `dev-publish-v1`.

In an isolated RC1 public source checkout, verify generated documents without changing them:

```sh
node scripts/generate-localized-markdown.mjs --check
node scripts/generate-localized-support.mjs --check
node scripts/generate-localized-policies.mjs --check
```

These commands check generated bytes and source bindings. They do not establish independent semantic review, native-speaker quality, host qualification, or deployment. The private development tree retains additional deferred locale files, so its RC1 checks use `--preserve-deferred` as specified by the private build procedure.

## Reference bodies and indexing

RC1 Architecture, Security, and CLI reference pages use localized navigation and headings with their canonical English bodies. A complete translated draft does not become an accepted public translation until independent semantic review. The following states describe both the RC1 body and deferred private drafts:

| Body state | Visible content | Independent semantic review | Search indexing |
| --- | --- | --- | --- |
| `canonical-english-body` | Localized navigation and headings with the canonical English body | `not-established` | `noindex,follow` |
| `translated-pending-review` | Complete translated draft body with source-owned commands and identifiers | `pending` | `noindex,follow` |

Catalog presence and structural parity alone do not make a reference guide an accepted translation. Auto quick-start routes may be indexed; the other Auto documentation routes stay `noindex,follow` until their content is accepted for indexing. Evidence Cinema is presentation-only and cannot serve as authoritative run evidence.

## Quality gates

For RC1, check locale membership and order, key parity, canonical and `hreflang` links, reference bindings, unresolved template tokens, and misleading translations of `fresh`. Maintain the English contract when correcting the Traditional Chinese copy. Structural checks do not substitute for semantic review or public readback. Any additional locale needs its own accepted V5.0.rc2 candidate.
