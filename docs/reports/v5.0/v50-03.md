## Private capture consumer hardening (2026-10-07)

On the later private base `6ce4f5905c8ca2f3fcf460c891b63218a9c44c46`, the actual protected capture client was found to destructure and spread caller options before invoking `snapshotJsonDataV1()`. That could invoke an option getter, and `Buffer.from(input)` could allocate before the 128 KiB request limit. The client now inspects own data descriptors without calling getters, rejects proxies and unrecognized options, bounds and copies string or Uint8Array input before base64 encoding, and snapshots the whole request before dispatch. The actual installed port calls the same function tested with a local request stub. The caller's options and input are read once and mutations after snapshot do not change the request.

The generated capture ID is part of the bounded snapshot, matching the broker's complete-request limit. The focused test now has eleven cases, including the largest reachable request below 128 KiB for a fixed ASCII input shape and the next rejected length, and passed under the pinned Node 22.23.3 and 24.21.0 runtimes. These tests exercise local request preparation and dispatch behavior; they do not start the root keeper or prove a formal protected capture. GOV-01, actual provider authority, and platform qualification remain separate gates.
